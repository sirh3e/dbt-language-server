1. Setup                                               *cogitator-nvim-setup*

Requires Neovim 0.11+ and the `cogitator` binary (a release asset or
`cargo build --release -p cogitator`). >lua

    require("cogitator").setup({})
<
The server attaches to `sql` and `yaml` buffers inside a dbt project (a
directory with `dbt_project.yml` upward from the file). Run
`:checkhealth cogitator` to verify the binary, the project root and the
profiles.yml resolution.

==============================================================================
2. Options                                           *cogitator-nvim-options*

Defaults shown: >lua

    require("cogitator").setup({
      cmd = { "cogitator" },      -- server command; flags are appended
      profiles_dir = nil,         -- profiles.yml dir → initializationOptions
      fusion = false,             -- true, or "/path/to/dbt" for Fusion mode
      tree_sitter = true,         -- false → --no-tree-sitter
      debug = false,              -- true → --debug (log.txt next to binary)
      filetypes = { "sql", "yaml" },
      root_markers = { "dbt_project.yml" },
      attach_outside_project = false, -- true: fall back to cwd as root
      lens = {
        enabled = true,
        events = { "BufEnter", "CursorHold", "InsertLeave" },
      },
      keymaps = true,             -- the buffer-local <leader>d maps below
      semantic_tokens = true,
    })
<
`profiles_dir` is sent as `initializationOptions.profilesDir`; the server
resolution order is: this override, `$DBT_PROFILES_DIR`,
`<root>/profiles.yml`, `<root>/.dbt/profiles.yml`, `~/.dbt/profiles.yml`.

3. Commands and keymaps                             *cogitator-nvim-commands*

  :DbtRun        dbt run for the current model       <leader>dr
  :DbtTest       dbt test for the current model      <leader>dt
  :DbtCompile    dbt compile; opens compiled SQL     <leader>dc
  :DbtParse      dbt parse; refreshes the context
  :DbtPreview    dbt show result rows ([limit], default 50)
  :DbtRelation   yank database.schema.identifier     <leader>dR
  :DbtProjects   pick a known dbt project            <leader>dP
  :DbtQuery      bounded SELECT on the relation      <leader>dx
  :DbtCache      derived-cache stats ('clear' empties)
  :DbtSchema     jump to the schema.yml entry        <leader>ds
  :DbtLineage    show column lineage (message)       <leader>dl
  :DbtGraph      model-graph browser                 <leader>dg
  :DbtBrowse     project-wide model browser          <leader>db
  :DbtProfiles   show/switch the profiles directory
  :DbtTarget     pick the active profile/target      <leader>dT
  :DbtExtract    model → schema YAML / add version   <leader>dy
  :DbtTests      jump to a test of this model        <leader>dq
  :DbtStatus     language-server status              <leader>dS
  :DbtDag        project DAG, dbt-docs style         <leader>dD
  :DbtTags       pick a tag, then a model
  :DbtSelectors  pick a selectors.yml entry

`:DbtDag` (a *Neovim-only* feature) draws the whole project as a layered
DAG in the dbt-docs colours. One node is selected, and movement goes
from node to node:

  h / l          a connected parent / child (nearest by row, or back the
                 way you came)
  j / k          next / previous node in the same layer
  gg / G         first / last node ([count] goes to that node)
  { / }          first / last layer ([count] counts from that end)
  /              search node names live; n / N step through the matches
  <C-o> / <C-i>  older / newer selection
  <CR>           open the selected model
  c / C          expand columns in this / every node (docglow-style)
  L              show column lineage
  R              refresh
  q              close

Counts repeat h, j, k, l, n, N, <C-o> and <C-i>. The colours are the
`DbtDag*` highlight groups, which a colorscheme can override. Search
also works through |vim.lsp.buf.workspace_symbol| with `tag:x` and
`selector:x` queries.

Context refreshes and dbt runs also report through $/progress, so they
appear in |vim.lsp.status()| and plugins like fidget.nvim.

A `cogitator.yml` at the project root configures the server and is
hot-reloaded on save (see the server README's "Configuration file");
`:DbtStatus` shows whether one is loaded and any parse error.

The server logs what it is doing to |vim.lsp.log| (`:LspLog`): context
refreshes and warnings at the default info level; set
`log.client_level: debug` in cogitator.yml (hot) or send `$/setTrace`
for per-request timing lines.
                 run the code lens on this line      <leader>dL

`:DbtProfiles` without an argument prints the server's profiles.yml
resolution order with the winning candidate marked. With a directory
argument it switches the directory LIVE through `dbt.setProfilesDir`
(no restart) and remembers the choice for this project in the manager
store; against older servers without that command it falls back to the
restart flow. `:DbtTarget` choices persist per project the same way,
and `:DbtProjects` picks among every project the store knows. The
store is a JSON file at `stdpath("data")/cogitator/manager.json`
(override with setup's `manager_path`); stored selections are injected
as initializationOptions on the next attach.

The graph browser (|:DbtGraph|) is a yazi-style three-pane float: direct
upstream models on the left, the current model in the center, direct
downstream models on the right. Keys inside it:

  h / l          from the center: enter the upstream / downstream pane
                 in a side pane: h upstream or l downstream walks one
                 step further along the lineage ([count] walks that
                 many); the opposite key returns to the center
  j / k          select an entry in a side pane
  <CR>           re-center the graph on the selected neighbor
  o              open the selected entry's file (center: the model itself)
  y              yank the selected entry's name
  q / <Esc>      close the browser

Sources appear in the upstream pane tagged `[source]`; they have no
further lineage behind them.

`:DbtBrowse` (a *Neovim-only* feature) is the project-wide browser:
the center pane lists every model, the side panes follow the selection
with its direct upstream and downstream, and the preview below shows
the selected model in four tabs. Keys inside it:

  j / k          select a model (the panes follow, debounced); counts
                 and the other native motions work (5j, gg, G, <C-d>)
  n / N          step through the list, wrapping at the ends
  /              filter the list live (smart-case substring);
                 <BS> edits, <CR> accepts, <Esc> clears
  h / l          from the center: enter the upstream / downstream pane
                 in a side pane: h upstream or l downstream re-centers
                 on the entry and stays, so pressing it again walks the
                 lineage ([count] walks that many); the opposite key
                 returns to the center
  p              focus the preview pane (h returns)
  J / K          scroll the preview from any pane
  <Tab>          cycle the preview tabs (<S-Tab> reverses)
  [count]<Tab>   preview tab [count]
  <CR>           side pane: re-select that model in the center
                 center: open the model file and close
  o              open the selected entry's file
  y              yank the selected model's or entry's name
  <Esc>          clear the filter first, close second
  q              close the browser

The preview has four tabs (1 raw / 2 compiled / 3 versions+tests /
4 info — description, tags, relation name, documented columns, and
tests whose <CR> jumps to their YAML entry). `:DbtExplorer` is an
alias of |:DbtBrowse|.

The compiled tab fetches `dbt.compiledSql` from the server (which reads
`target/compiled/<project>/…`) and never runs dbt — when nothing is
there it shows a hint to run |:DbtCompile| instead.

Code lenses on each model: "N downstream", "N upstream", "Go to schema",
"Column lineage", "dbt run", "dbt test", "dbt compile"; macros get an
informational "N call sites" lens (not executable).

The same command set is served as code actions
(|vim.lsp.buf.code_action|): on a `ref('x')` an "Open schema of 'x'"
action is added, and inside a schema YAML the model entry under the
cursor offers "Open model" and "Go to tests".

dbt run/test/compile are asynchronous; progress and results arrive as
notifications (`:messages` keeps them).

==============================================================================
4. Caveats                                           *cogitator-nvim-caveats*

- Rename (|vim.lsp.buf.rename()| on a model or `ref`) rewrites dependents,
  the schema.yml entry, and renames the model file. Dependents are read
  from disk: save other modified buffers before renaming.
- Completion ranking comes from the server via `sortText`; keep your
  completion engine's sortText comparator enabled.

==============================================================================
5. Neovim 0.10 fallback                                 *cogitator-nvim-0.10*

Without |vim.lsp.config()|, configure through nvim-lspconfig: >lua

    require("lspconfig.configs").cogitator = {
      default_config = {
        cmd = { "cogitator" },
        filetypes = { "sql", "yaml" },
        root_dir = require("lspconfig.util").root_pattern("dbt_project.yml"),
        init_options = { profilesDir = nil },
      },
    }
    require("lspconfig").cogitator.setup({
      capabilities = vim.tbl_deep_extend("force",
        vim.lsp.protocol.make_client_capabilities(), {
          window = { showDocument = { support = true } },
          workspace = { workspaceEdit = {
            documentChanges = true,
            resourceOperations = { "rename" },
          } },
        }),
    })
<
